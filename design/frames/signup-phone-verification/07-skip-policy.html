"Skip for now" — both policy outcomes

The ticket doesn't settle whether phone is mandatory, so both outcomes are designed, with one server-driven switch, AuthMethods.verification.phoneAtSignup: "off" | "optional" | "required" (Δ). Recommended default: optional. Even required never blocks account creation and is never a dead end. It removes the user's own Skip, but in any failure state (including a network error or an unclassified 5xx) the user can continue, and is re-prompted at next sign-in.
