When the text can't be sent

Each failure gets its own honest screen, and every one has a way forward (retry, change number, or continue). Today any send failure falls through sendError to 401 UNKNOWN "Authentication failed", which looks to the client like the session ended. The manifest asks for 502 SMS_SEND_FAILED, 503 SMS_UNAVAILABLE, 429 RATE_LIMITED, 400 PHONE_INVALID, and 409 PHONE_UNAVAILABLE (Δ).

error-number-unavailable · number in use (409, no enumeration)

409 PHONE_UNAVAILABLE is returned only by /confirm, after a correct code. /start answers 202 for any well-formed number, so someone without the phone can't probe whether a number is registered. Only the phone's owner ever sees this screen, and the copy still doesn't confirm another account exists.
