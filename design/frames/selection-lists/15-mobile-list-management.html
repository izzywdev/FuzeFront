Rules the implementation must keep

  • At ≤ 40em (≈ 640 CSS px) the shell's side navigation collapses to the menu button (DS Drawer), and every table in this flow renders as one card per row: name first, then key, count and status. Owner and last-updated are not dropped — they live on the list's detail.
  • Touch targets are at least the DS --touch-target (44 px) — buttons, inputs, tabs, drag handles and the row-actions button. No horizontal scroll at 375 px; the tab bar may scroll sideways on its own.
  • Row actions move into a “More actions” sheet with exactly the desktop actions for that row — Edit / Archive for active values, Restore / Delete… for archived ones. Delete still opens the typed-confirmation dialog of frame 1d; a phone never gets a shorter path to a purge.
  • Reorder works without a keyboard and without precise dragging. Long-press lifts a row (pointer drag), and a lifted row shows Up / Down / Done buttons that do what ↑ / ↓ / Space do on desktop. Each move is announced in the live region; the drop sends the full permutation; a failed save puts rows back.
  • Dialogs become the DS BottomSheet (max height --sheet-max-h) with stacked full-width actions, primary action last (nearest the thumb). Code stays locked on edit and the sli_… id is still shown.
  • A disabled CTA explains itself in visible text directly under the button (aria-describedby), because a tooltip cannot be hovered on touch. Quota failing open (frame 1f) is unchanged.
  • RTL (he, ar): direction comes from the locale, layout uses logical properties, keys and codes are LTR islands, and the row chevron mirrors; the drag-handle glyph does not.
