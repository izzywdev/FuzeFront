Selection Lists — Approval Frames

Fourteen navigable frames covering the org-admin management UI, the translation workbench, per-list access control, and the embeddable <SelectionListPicker>. Approving them freezes the visual and interaction contract — and the build inventory below — before any feature UI is written. Built in the fuse-seam design system (tokens only).

ℹ

Approval is per flow

Each of the four flows below is approved independently. Approving Flow 1 unblocks its implementation immediately; the other three can keep iterating. No ready flow waits on an unready sibling.

Flow 1 · List management

● Awaiting approval
SelectionListManagementFlow → /settings/selection-lists · org admin / list owner

Create a list, curate its values, order them deliberately, and stay inside the org's quota ceilings. Values carry an immutable service-minted id (what consuming apps persist), an immutable interop code, and a translatable label.

Frame 1a

List index

Paginated table with status filter and search. Loading, empty and error states.
Frame 1b

New list

Name, immutable key with slug validation, source locale. Inline 400 / 409 / 403 handling.
Frame 1c

List detail / value editor

Tabbed detail with the ordered value table. Archive vs purge made explicit. Includes 404-not-403.
Frame 1d

Add / edit value

Code locked after create, id revealed, purge behind typed confirmation.
Frame 1e

Reorder — drag in progress

Lifted row, drop target, keyboard-reorder contract, and rollback when the save fails.
Frame 1f

Quota warning & wall

All four ceilings, the ≥80% warning, and the at-limit disabled CTA with its tooltip.

Flow 2 · Translation workbench

● Awaiting approval
TranslationWorkbenchFlow → /settings/selection-lists/:listId/translations · translator

Runtime i18n for org-authored content across 11 locales. Machine output is always badged, human work is never overwritten, and a changed source is flagged rather than silently stale. RTL (ar, he) flips the target column, not the source.

Frame 2a

Translation index

Per-locale completion, source marked, machine counts, and start/autofill CTAs.
Frame 2b

Locale editor

Source beside translation, M badges, source_hash mismatch warning, RTL layout.
Frame 2c

Autofill confirmation

States the count and the source locale, and guarantees human strings survive. Partial-failure state.

Flow 3 · Access control

● Awaiting approval
SelectionListAccessFlow → /settings/selection-lists/:listId/access · list owner / org admin

Per-list ReBAC with action granularity — five non-stacking roles. The load-bearing state is last-owner protection: demoting or revoking the sole list-owner returns 409 CONFLICT, shown inline on that row.

Frame 3a

Access panel

Grants table, role matrix, and the 409 last-owner refusal.
Frame 3b

Add access

Member search with already-granted marking, role select with plain-language descriptions.

Flow 4 · SelectionListPicker

● Awaiting approval
SelectionListPicker → embeddable (harness route /embed/selection-list-picker) · consuming products

The embeddable component every consuming product mounts. Shown in a generic host form — not in the FuzeFront shell — because that is where it actually lives. It persists the item id and re-resolves the label per viewer, per locale.

Frame 4a

Single select

Combobox bound by list key, in authored sort order. Loading, empty, error, 404.
Frame 4b

Multi select

Chips, clear-all, no-matches filtering, and a host-imposed max.
Frame 4c

Archived value resolved

A stored id whose value was archived still renders its label, greyed and badged — never blank. Contrasted with a purged id.
