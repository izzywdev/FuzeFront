New selection list

The service mints the list id (sl_…) — you never supply one. You are granted list-owner on the list you create.

Written to the source locale translation. Other locales are added later in the translation workbench.

✕ Lowercase letters, digits and hyphens only — try lead-status.

🔒 Immutable after create — integrations address the list by this key, so it cannot be renamed. Must be unique in the organization (409 CONFLICT otherwise).

Optional. Also stored in the source locale.

The language you author in. Every other locale falls back to it, and machine translation translates from it. 11 supported locales.

Cancel

States

The create call is the one most likely to be refused — by validation, by a duplicate key, or by quota.

⚠

That key is already used — 409 CONFLICT

A list with key lead-status already exists in this organization. Keys are unique per org and cannot be reused, even by an archived list.

⚠

Organization list quota reached — 403 QUOTA_EXCEEDED

Scope org_lists · 100 of 100 used. Archive a list you no longer need, or ask an org admin to raise the ceiling. See quota.

⚠

You can't create lists here — 403 FORBIDDEN

Creating a list needs org admin or manage_access. The + New list button is disabled rather than hidden, so the limit is legible.

submitting Submit is disabled and both fields are read-only while the create is in flight — double-submit would race two keys.
