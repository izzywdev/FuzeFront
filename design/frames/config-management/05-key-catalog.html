Key catalog — what a setting is

The editor answers "what is this value?". The catalog answers "what is this key?" — how it validates, where it may be set, who may change it, and whether it is system, hidden, secret or deprecated. This is the platform-admin surface, and the only place hidden keys are ever visible.

Hidden keys are visible on this screen and nowhere else. Reaching this route requires a platform-admin grant. The two isHidden rows above are absent from every GET /v1/config response the settings editor makes — see frame (c). If a non-platform-admin can load this table, that is a disclosure bug, not a styling bug.

Contract. GET /v1/namespaces and GET /v1/namespaces/{namespace}/keys → PagedKeyDefinitions; each row is one KeyDefinition (valueType, allowedScopes, isSystem, isHidden, isSecret, isReadonly, requiresRestart, deprecatedAt, replacedBy, defaultValue).
Read-only surface. This flow does not edit definitions — key-definition authoring is FF-EPIC-18-S6 (declarative registration from an app manifest), not a console form.
