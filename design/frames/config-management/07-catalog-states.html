Catalog states

Four of these look similar and mean completely different things: no namespaces exist, this namespace declares no keys, your search matched nothing, and you may not see this at all. Rendering one generic "nothing here" for all four is the failure this frame prevents.

A · Loading

Skeleton rows in the table's own column rhythm, so the header does not reflow when definitions land.

KeyTypeSettable atFlagsDefault
B · No namespaces registered — first run

Nothing has ever registered configuration. This is a setup state, not a failure, and its call to action is documentation, not "retry".

No configuration namespaces yet

No application has registered a configuration namespace on this platform. Namespaces are declared by an app's manifest, not created by hand in this console.

C · Namespace exists, declares no keys

Distinct from B: the namespace is real, so the fix is with that app, and the screen names it.

reporting

0 key definitions

The reporting namespace declares no keys

It is registered but has published no key definitions. Nothing will appear in the settings editor for this namespace at any scope.

D · Search matched nothing

Keys do exist — the filter excluded them. The state must offer to clear the filter, and must never be reachable when the underlying list is genuinely empty (that is B or C).

No keys match “webhook” with Secret selected

8 key definitions exist in notifications.

E · Load failed

Could not load the key catalog. The configuration service did not respond. No configuration has been changed.

F · Not a platform admin — fail closed, and nothing loads

The most important state in this flow. Because the catalog is the only surface exposing isHidden keys, a partial render here is a disclosure. There is no "greyed-out table with the rows still in the DOM" — the request is refused and no definition data reaches the browser at all.

You do not have access to the key catalog. FORBIDDEN Viewing key definitions requires a platform administrator grant. Your organization's settings remain available in the settings editor.

Go to settings

QA asserts on the network response, not on the rendered table: a spec that only checks "no rows visible" passes against a build that fetched every hidden key and hid it with CSS.

Contract. GET /v1/namespaces → PagedNamespaces (state B), GET /v1/namespaces/{namespace}/keys → PagedKeyDefinitions (states C, D), FORBIDDEN from ErrorCode (state F). Permit decides; the console reflects.
