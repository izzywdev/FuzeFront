Flow 1 · Settings editor · Frame (c) · /config

Editor states — before there is anything to edit

States are contract, not decoration. A frame set that shows only the populated editor produces an editor that handles only the populated case. Each block below is a state the implementation must render and QA must drive.

A · Loading

Skeleton rows preserve the two-column key/value rhythm so the layout does not jump when entries arrive. No spinner-over-empty-form: an empty form is indistinguishable from "this namespace has no settings".

B · Empty namespace — entries: []

The namespace is registered but declares no visible keys at this scope. This is a legitimate 200, not an error and not a "no results" — the search box must not be blamed. It is also what a user sees when every key in the namespace is hidden (see D).

No settings in this namespace

The notifications namespace is registered but has no keys you can see or set at org Acme Corp. Nothing is wrong — there is simply nothing to configure here yet.

C · Load failed

Retryable, and it must never present an empty form the user could type into and "save" — the editor has no baseline version to send as expectedVersion, so a write here could clobber a concurrent edit.

Could not load settings for this scope. The configuration service did not respond. Your existing settings are unchanged — nothing has been saved or lost.

D · System-hidden keys — absent entirely, not hidden in the DOM

This is the state most likely to be built wrong, because building it wrong looks identical on screen. Hidden keys are omitted by the API; the editor performs no client-side filtering and must have no code path that could render one. A hidden key that arrives, is rendered, and then CSS-hidden has already leaked into the browser.

Every entry arrives with editable: false. The editor renders the whole surface read-only with no save bar at all — never inputs and a Save button that only 403s. The UI is not the authorization boundary; it reflects a decision Permit already made.
