Fail-closed rules

  • A 409 without reason (key taken, last owner, …) is the ordinary conflict message from the 4.0.0 frames — the fork banner renders only for reason: fork_required.
  • The Fork CTA uses source_list_id from the error body, not the id in the page URL — the 409 names the list the service refused.
  • fork_url is relative (/v1/…) and is resolved against the same-origin API base. A body carrying an absolute URL is ignored and the client's own forkList(sourceListId) is used.
  • The refusal never auto-forks. Forking creates a list in the organization and costs quota — it is always an explicit choice in the next dialog.
  • Flag OFF: the service answers 4.0.0 behaviour and no common list is reachable, so this banner cannot appear; the UI does not render it even if a stray reason arrives.
