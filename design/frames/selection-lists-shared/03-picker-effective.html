Bound to key="priority", exactly as before. What changes is which list that key means.

ℹ

One lookup, one rule — the picker never chooses between lists itself

The picker calls getEffectiveList("priority") → GET /v1/selection-lists?key=priority&include_shared=true&limit=1. The service returns the effective list: your organization's own readable active list with that key (normally its fork) if there is one, else the active common list. The picker renders whatever comes back. It never fetches both and never merges them. Host forms change nothing — the key is the same, and the form still submits the item id.
