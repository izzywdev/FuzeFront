⚑

Contract dependency (for contract-designer, not for users)

Contract 4.1.0 exposes the copied revision (SelectionListForkProvenance.revision, “a consumer comparing it with the source's current revision can tell the fork is behind”) but SelectionList has no revision property, so the current revision is not readable over HTTP. The behind / up-to-date states need an additive, read-only SelectionList.revision (integer ≥ 1, the event contract's listRevision) — a MINOR. Until it ships the UI renders comparison unavailable, which is honest and complete; this flow (fork-provenance) can be approved independently of it.

Revert to the common list = archive your fork

Archiving the fork only sends forms back to the common list if an active common list with the same key exists: the effective-list lookup considers the organization's own active list, then the active common list, then nothing. So the action, and what its confirmation promises, follow the provenance read above.

Why the 404 copy is conditional

A 404 on the source read means “purged or not readable by you” — the contract makes the two indistinguishable on purpose. The common list may still be active and readable by other members (for example if your own role lost shared read), so their forms would fall through to it. The UI therefore states the consequence under its condition and never claims every form becomes unavailable. Cancel is the safe default and holds initial focus.
