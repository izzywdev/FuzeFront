Body sent — and what is never sent

Request
POST /v1/selection-lists/front_sl_01jf8k2m3n4p5q6r7s8t9v0w1x/fork
{ "visibility": "org" }

No id, no key, no name — the service mints every id and the fork keeps the key (additionalProperties: false; a body carrying an id is a 400). The source id comes from the page's list, or from source_list_id when the dialog was opened from a 409 fork_required.

Double-submit is harmless — the service is idempotent per (organization, source) and a repeat answers 200 with the same fork — but the button is still disabled while in flight.

Flag OFF: the dialog is never mounted (no CTA leads to it), and the service answers 404 on …/fork anyway. Mobile and RTL presentation: frame 12.
