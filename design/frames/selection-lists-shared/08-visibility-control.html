Changing it

Organization → Private: confirm the consequence

Make Priority private?

  • Members without a role can no longer see it.
  • Their forms use the common Priority list instead, if one is active — otherwise those forms show “List unavailable”.
  • Values saved from the common list show the common labels again.
  • Values picked from your fork keep showing your fork's labels — they belong to Acme Logistics and still resolve.
  • Nothing is deleted; switch back to Organization at any time.

Private → Organization saves without a confirm (it only widens reading) and toasts “Everyone in Acme Logistics can now see Priority.” The fork-specific lines render only when forked_from is set.

Why the two stored-value lines differ: POST /v1/resolve resolves every item id of the caller's own organization (no per-list read check), so ids picked from the fork keep their fork labels whatever the fork's visibility. Only common-list ids change: they stop being redirected to the fork's labels, because a private fork never redirects. The forms line stays conditional because this page does not read the common list's status; the effective-list lookup only falls through to an active common list.
