Connected Accounts — Approval Frames

The connected-accounts surface reached from the security hub's "Connected accounts" card (/account/security/connections). It's where a person connects a sign-in provider (Google), sees their linked providers + password, and disconnects one — always keeping at least one way to sign in. These frames freeze the connect/disconnect model before UI is built. Rendered in the fuse-seam design system (tokens only). No identity-vendor name ever appears — the browser only ever sees app.fuzefront.com and, during a link, accounts.google.com.

Walk the flow

Frame (a) · route /account/security/connections

Connections list

Password method + each linked provider (Disconnect), plus a "Connect Google" affordance for providers not yet linked. Reads GET /identity/connections.
Frame (b) · connect flow

Connect a provider

Redirect intent (POST /social/google/link → redirectUrl → accounts.google.com) and the successful return on ?linked=google.
Frame (c) · states

States & fail-closed

Loading, load error + retry, social-only (hasPassword:false → set a password first), last-method 409 guard, connect failed/cancelled, already-linked.
