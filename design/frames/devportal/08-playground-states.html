Playground — the fail-closed states

This is the part of the feature where a wrong state is a security incident, not a cosmetic bug. Every failure below has one non-negotiable property: it never falls back to production. A sandbox that is unavailable produces an error, never a live call.

A 409 from the target is the API behaving correctly and is rendered as a response, not as a portal failure callout. Only the portal's own failures (c, d, f, g) use StatusCallout. Confusing the two is how a playground trains developers to ignore errors.
