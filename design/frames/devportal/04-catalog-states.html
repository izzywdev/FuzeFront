Catalog — loading, empty, filtered-empty, error, forbidden

States are contract, not decoration. A catalog that only draws the populated case produces a UI that only handles the populated case. Five states below; each is a distinct thing the API can hand us, and each tells the developer what to do next.

(a) Loading · GET /catalog in flight

Skeletons preserve the populated layout so nothing jumps on arrival. aria-busy="true" on the results region; no spinner-only screen.

(b) Empty · 200 with zero specs — nothing has been harvested yet
📭

No specs have been published yet

The catalog is built from specs that repos publish on merge. Nothing has arrived yet — this is a cold start, not a failure.

How to publish your spec

Distinct from (c): this is zero specs in the registry. Copy points at the one-step CI action that fixes it, rather than leaving a dead end.

(e) Forbidden · 403 from Permit — signed in, but not a Developer yet
🔒

Your account doesn't have developer access yet

Reading the catalog needs DevPortalCatalog:read, granted by the Developer role on the platform root organization. Provisioning normally happens on first sign-in; if it hasn't completed, or the capability is still flag-gated for your account, it lands here. We do not silently show a partial catalog — this fails closed.
