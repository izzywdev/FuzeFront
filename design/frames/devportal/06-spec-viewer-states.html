Spec viewer — loading, fetch failed, invalid spec, not found, stale

A spec can be slow, missing, unreachable, or present but not valid OpenAPI. The last one is the interesting case: an invalid spec must not render as a half-broken doc page with a "Try it" button that fires nonsense. It fails closed, names the offending source repo, and disables the Playground for that spec.

(a) Loading · spec blob + renderer bootstrapping

The spec header is rendered from catalog data we already have — name, product, version — so only the panes that need the blob show skeletons. Nothing reflows when the spec lands.
