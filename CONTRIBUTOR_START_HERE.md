# Contributor: Start Here

Welcome to FuzeFront.

If this is your first contribution, do not begin by trying to understand the entire Software Factory. Pick one narrow surface, reproduce one behavior, and improve one thing.

## Best first contributions

Good first contributions usually fall into one of these categories:

- documentation that is outdated, ambiguous, or inconsistent;
- setup steps that fail on a clean machine;
- example-app improvements;
- missing tests for documented behavior;
- accessibility fixes;
- Hebrew/RTL or internationalization fixes;
- small SDK examples;
- developer-experience improvements with clear before/after behavior.

## Before you code

1. Read `COMMUNITY.md`.
2. Read `CONTRIBUTING.md`.
3. Choose an issue with `[Good first issue]` in the title.
4. Comment that you want to work on it before starting.
5. Keep the PR focused on that issue.

## What makes a strong first PR

A strong first PR is small, reproducible, and easy to review. Include:

- what was wrong or missing;
- how to reproduce it;
- what you changed;
- how you verified the change;
- screenshots or command output when relevant.

## Need a task?

Browse the open issues:

https://github.com/izzywdev/FuzeFront/issues

If the existing tasks are not a fit, use the **Good first issue proposal** template and suggest a small improvement you found while exploring the repo.
