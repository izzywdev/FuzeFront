# Community Roadmap

This roadmap tracks work that makes FuzeFront easier to evaluate, adopt, challenge, and contribute to.

## Phase 1 — Make evaluation easy

- Verify the quickstart on clean environments.
- Remove naming drift between FrontFuse and FuzeFront.
- Improve first-run troubleshooting.
- Document the smallest possible app-integration example.
- Publish architecture comparisons and explicit non-goals.

## Phase 2 — Make contribution easy

- Maintain newcomer-sized issues.
- Improve contribution templates and review expectations.
- Add more tests around documented public behavior.
- Improve accessibility and internationalization coverage.
- Create examples that can be changed safely without deep platform knowledge.

## Phase 3 — Make adoption measurable

- Track time-to-first-run.
- Track time-to-onboard an existing application.
- Capture recurring integration pain.
- Publish design-partner lessons where permission allows.
- Turn common manual fixes into platform automation.

## Phase 4 — Build an ecosystem

- Integration adapters.
- Reusable app templates.
- Community examples.
- Public architecture proposals.
- Extension points and plugin patterns.
- Documentation contributed by real adopters.

## Guiding rule

Community work should improve one of four things: **time to understand, time to run, time to contribute, or time to production**.
