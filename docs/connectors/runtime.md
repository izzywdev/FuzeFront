# Connector runtime (first ten providers)

The Connectors page shows ten provider connections in addition to the existing Gmail integration. Each account authorization has an independent callback, FuzeKeys credential record, and read action. FuzeKeys must be deployed with its provider-scoped connector routes before enabling these flows. Apply backend migration `028_connector_oauth_nonces` before accepting callbacks; the database enforces one-time OAuth state consumption across replicas.

## Required deployment configuration

Set `CONNECTOR_STATE_ENCRYPTION_KEY` to a stable secret with at least 32 characters, identical on every backend replica. Configure each provider's OAuth client and register the exact callback generated by the Helm chart. The following keys are read from the backend's Kubernetes secret; missing keys leave that provider unavailable:

| Provider | Credential keys | Callback environment variable | Read action |
| --- | --- | --- | --- |
| Google Drive | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `GOOGLE_DRIVE_OAUTH_REDIRECT_URI` | `files` |
| Google Calendar | same Google keys | `GOOGLE_CALENDAR_OAUTH_REDIRECT_URI` | `events` |
| Google Contacts | same Google keys | `GOOGLE_CONTACTS_OAUTH_REDIRECT_URI` | `contacts` |
| Outlook Mail | `MICROSOFT_OAUTH_CLIENT_ID`, `MICROSOFT_OAUTH_CLIENT_SECRET` | `MICROSOFT_OUTLOOK_REDIRECT_URI` | `recent` |
| OneDrive | same Microsoft keys | `MICROSOFT_ONEDRIVE_REDIRECT_URI` | `files` |
| Microsoft Teams | same Microsoft keys | `MICROSOFT_TEAMS_REDIRECT_URI` | `chats` |
| Slack | `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET` | `SLACK_REDIRECT_URI` | `channels`, `messages` |
| Notion | `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET` | `NOTION_REDIRECT_URI` | `pages` |
| GitHub | `GITHUB_CONNECTOR_CLIENT_ID`, `GITHUB_CONNECTOR_CLIENT_SECRET` | `GITHUB_CONNECTOR_REDIRECT_URI` | `repositories`, `issues` |
| Dropbox | `DROPBOX_CONNECTOR_CLIENT_ID`, `DROPBOX_CONNECTOR_CLIENT_SECRET` | `DROPBOX_CONNECTOR_REDIRECT_URI` | `files` |

Use a private Helm values file under `secret.connectorOAuth` or an existing managed secret. Google credentials reuse the existing `secret.googleClientId` and `secret.googleClientSecret`. Set `secret.connectorStateEncryptionKey` or provide `CONNECTOR_STATE_ENCRYPTION_KEY` in the existing secret. Do not commit provider secrets.

The authenticated API exposes `GET /api/v1/connectors/catalog`, account status at `/:provider`, `POST /:provider/connect`, `DELETE /:provider`, and read operations at `/:provider/actions/:action`. Provider credentials remain in FuzeKeys and are leased only for the authorized user's request. The existing Gmail chat path remains separate.

Provider marketplace publishers live in `packages/connector-publisher`; see [publishing](publishing.md). Those agents prepare provider-specific submission packets. OAuth client registration, brand assets, provider-native app surfaces, external review, and store approval still have to be completed for public listings.
